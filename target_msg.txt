quality(matrix): write the tier row's counts from the measurement

The row was already pinned to the probe by
`test_the_test_matrix_rows_state_the_counts_the_probe_measures`, so a stale
digit is a red run rather than a lie. What was missing is a way to produce
the right digit: PR #549 reddened all 14 test legs because adding a test file
moves the count and nobody can be told to remember that, and two open
pull requests that both move the row force a replay of whichever lands second
(measured today: #549 -> #550, #552 -> #553).

`ROW_RULES` + `row_drift`/`apply_rows` now own the four count-bearing
sentences of section 1 and 4: each rule keeps the prose and recomputes only
the number, so `--write-rows` is the same measurement the checker uses and
`--check-rows` prints the drift. A rule whose pattern stops matching is
reported rather than skipped, because the silent version of this failure is a
table reworded until nothing is checked - the shape this file keeps refusing
for role conditions.

Demonstrated while rebasing this branch onto `47349338`: the Python count moved
1,822 -> 1,824 (#553 adds tests too) and
`python scripts/quality_matrix.py --write-rows` printed
`wrote 1 row sentence(s): unit / integration row` and was clean.

Controls in `tests/test_quality_matrix.py`: the committed page equals what
`apply_rows` writes; a stale digit is named by row and by value; a reworded
row is named as unparseable and a rewrite does not invent it; repair is
idempotent.
