title: サイト全体の i18n 機能ガイド
lang: ja


## 概要

pyrs-yaml のドキュメントは、MkDocs Material テーマの組み込み i18n 機能を使用して **サイト全体の国際化** をサポートしています。ユーザーは以下の言語でドキュメントを表示できます：**English (en)**、**中文 (zh)**、**日本語 (ja)**、**한국어 (ko)**。

## 動作原理

Material テーマは `mkdocs.yml` の設定を通じてネイティブの i18n サポートを提供します。各言語は独自の URL パス（`/zh/`、`/ja/`、`/ko/`）を持ち、統一されたナビゲーションと言語切り替え機能を使用します。

```yaml
plugins:
  - i18n:
      docs_structure: folder
      languages:
        - locale: en
          default: true
          name: English
          build: true
        - locale: zh
          name: 中文
          build: true
        - locale: ja
          name: 日本語
          build: true
        - locale: ko
          name: 한국어
          build: true
```

ナビゲーションは、レンダリングされたサイトの右上隅に言語切り替えボタンを表示します。

## 新しい言語の追加

新しい言語（例：フランス語）を追加する手順：

#### 1. mkdocs.yml を更新

`mkdocs.yml` を編集して新しい言語を追加：

```yaml
plugins:
  - i18n:
      docs_structure: folder
      languages:
        - locale: en
          default: true
          name: English
          build: true
        - locale: zh
          name: 中文
          build: true
        - locale: ja
          name: 日本語
          build: true
        - locale: ko
          name: 한국어
          build: true
        - locale: fr
          name: Français
          build: true
```

必要に応じて、テーマのデフォルト言語も更新：

```yaml
theme:
  name: material
  language: en   # テーマのデフォルトフォールバック言語を設定
```

#### 2. 言語ディレクトリ構造の作成

```bash
mkdir docs/fr
mkdir docs/fr/guides
mkdir docs/fr/api
mkdir docs/fr/contributing
mkdir docs/fr/performance
```

#### 3. ドキュメントファイルの翻訳

英文ルートディレクトリからすべての markdown ファイルを新しい言語のサブディレクトリに翻訳。各翻訳ファイルは：

- 同じ相対パス構造を維持
- YAML frontmatter に言語メタデータを含む（以下参照）

#### 4. frontmatter の追加

各翻訳 markdown ファイルには、言語識別を含む YAML frontmatter **が必要**。これは MkDocs がファイルとその言語を正しく関連付けるために必要：

```yaml
---

title: ドキュメントタイトル
lang: ja
---
```

例：`docs/index.md` → `docs/ja/index.md` に翻訳：

## 翻訳前 (index.md)：

```markdown
# pyrs-yaml

**High-performance Python YAML library...**
...
```

### 翻訳後 (docs/ja/index.md)：

```yaml
---
title: pyrs-yaml
lang: ja
---

# pyrs-yaml

**高パフォーマンスな Python YAML ライブラリ...**
...
```

## 5. ナビゲーションタイトルの翻訳

各翻訳ファイルのすべてのナビゲーション項目タイトルを更新し、対象言語に一致させます：

- `Home` → `首页` (zh)、`ホーム` (ja)、`홈` (ko)
- `Quick Start` → `快速开始` (zh)、`クイックスタート` (ja)、`빠른 시작` (ko)
- `API Reference` → `API 参考` (zh)、`API リファレンス` (ja)、`API 참조` (ko)

## 翻訳プロセス

### 手動翻訳チェックリスト

各言語について、以下を確認：

- [ ] `/lang/` ディレクトリにすべてのトップレベル markdown ファイルが存在
- [ ] すべてのサブディレクトリ（`guides/`、`api/`、`contributing/`、`performance/`）に翻訳コンテンツがある
- [ ] 各翻訳ファイルに正しい `lang:` フィールドを持つ YAML frontmatter がある
- [ ] 要約が適切に翻訳されている
- [ ] リンク参照が正しい相対パスを使用している（リンクに言語プレフィックスなし！）
- [ ] 翻訳ファイルに未翻訳の英文見出しが残っていない

## 重要な注意事項

### ナビゲーション内のリンク参照

**内部ナビゲーションリンクに言語プレフィックスを含めないでください。** リンクは閲覧している言語に関係常に同じ相対パスを使用する必要があります：

✅ **正しい：**

```markdown
- **[クイックスタート](quick-start.md)**
- **[API リファレンス](api/reference.md)**
```

❌ **誤り：**

```markdown
- **[クイックスタート](ja/quick-start.md)**  # 誤り！
- **[API リファレンス](ja/api/reference.md)** # 誤り！
```

Material テーマは言語ルーティングを自動的に処理します。各言語バージョン内のすべてのリンクは、**同じ言語コンテキスト** 内の他のページを指す必要があります。

#### frontmatter 要件

各翻訳 markdown ファイルには YAML frontmatter **が必要**。最低限必要なフィールド：

```yaml
---
title: ページタイトル（翻訳済み）
lang: LANG_CODE
---
```

- `title`：翻訳されたページタイトル（ブラウザタブ、検索結果に表示）
- `lang`：i18n 設定と一致する言語コード（`languages` の `locale` のいずれかと一致する必要がある）

#### 言語間の一貫性

すべての翻訳は原文と **構造的一貫性** を維持する必要があります：

- 同じ見出し階層（#、##、###）
- 同じリスト項目と順序
- 同じコード例（説明テキストは翻訳）
- 同じテーブル構造（適切にタイトル/コンテンツを翻訳）

#### 特別な考慮事項

##### ライセンスファイル

ライセンスファイルは、軽く翻訳すべきでない法的用語を含むため、特別な注意が必要。実際のライセンステキストは英文のまま（法的正確性）にし、周囲の説明テキストのみを翻訳するのが一般的です：

```markdown
# ライセンス

pyrs-yaml はデュアルライセンス：

- [MIT ライセンス](https://github.com/MuLong/pyrs-yaml/blob/main/LICENSE-MIT)
- [Apache ライセンス, Version 2.0](https://github.com/MuLong/pyrs-yaml/blob/main/LICENSE-APACHE)
```

ライセンスの **テキスト自体** は英文のまま。セクション見出しと説明のみが翻訳されます。

##### コード例

コード例はすべての言語で **変更すべきではありません** — 実行可能で、英文/Python/Rust 構文のままにする必要があります：

```python
import pyrs_yaml

doc = pyrs_yaml.parse("key: value")  # 翻訳しないでください
```

コードブロック内の注記文字列のみ、明確さのために翻訳してもかまいません。

## 検証

ローカルドキュメントサイトをビルドして、i18n が正しく機能するか確認：

```bash
# 依存関係のインストール
uv sync

# サイトのビルド
mkdocs build --clean-site

# ローカルで提供
mkdocs serve
```

`http://localhost:8000/` にアクセスし、右上の言語切り替えボタンをクリックして、すべての言語が正しく読み込まれることを確認。

### トラブルシューティング

| 問題 | 解決策 |
|------|--------|
| 言語切り替えが表示されない | `mkdocs.yml` で `i18n` ブロックが正しく設定され、すべての代替言語に一致するディレクトリがあることを確認 |
| 翻訳バージョンのリンクが壊れている | 内部リンクに言語プレフィックスが含まれていないことを確認（相対パスのみ使用） |
| Frontmatter が解析されない | すべての翻訳ファイルが markdown コンテンツの前に `---` YAML frontmatter で始まることを確認 |
| 言語間で検索が機能しない | MkDocs material プラグインは言語ごとに個別の検索インデックスを生成；`--clean-site` で再ビルド |
