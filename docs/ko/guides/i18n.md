## 전역 i18n 기능 가이드

### 개요

pyrs-yaml 문서는 MkDocs Material 테마의 내장 i18n 기능을 사용하여 **사이트 전체 국제화**를 지원합니다. 사용자는 다음 언어로 문서를 볼 수 있습니다: **English (en)**、**中文 (zh)**、**日本語 (ja)**、**한국어 (ko)**.

### 작동 원리

Material 테마는 `mkdocs.yml`의 설정을 통해 네이티브 i18n 지원을 제공합니다. 각 언어는 고유한 URL 경로(`/zh/`, `/ja/`, `/ko/`)를 가지며, 일관된 탐색과 언어 전환 기능을 사용합니다.

```yaml
plugins:
  - i18n:
      docs_structure: folder
      languages:
        - locale: en
          default: true
          name: English
          build: true
        - locale: zh
          name: 中文
          build: true
        - locale: ja
          name: 日本語
          build: true
        - locale: ko
          name: 한국어
          build: true
```

탐색은 렌더링된 사이트의 오른쪽 상단 모서리에 언어 전환 버튼을 표시합니다.

### 새 언어 추가

새 언어(예: 프랑스어)를 추가하는 단계:

#### 1. mkdocs.yml 업데이트

`mkdocs.yml`을 편집하여 새 언어를 추가：

```yaml
plugins:
  - i18n:
      docs_structure: folder
      languages:
        - locale: en
          default: true
          name: English
          build: true
        - locale: zh
          name: 中文
          build: true
        - locale: ja
          name: 日本語
          build: true
        - locale: ko
          name: 한국어
          build: true
        - locale: fr
          name: Français
          build: true
```

필요한 경우 테마의 기본 언어도 업데이트:

```yaml
theme:
  name: material
  language: en   # 테마의 기본 폴백 언어 설정
```

#### 2. 언어 디렉토리 구조 생성

```bash
mkdir docs/fr
mkdir docs/fr/guides
mkdir docs/fr/api
mkdir docs/fr/contributing
mkdir docs/fr/performance
```

#### 3. 문서 파일 번역

영문 루트 디렉토리에서 모든 markdown 파일을 새 언어 하위 디렉토리로 번역. 각 번역 파일은:

- 동일한 상대 경로 구조 유지
- YAML frontmatter에 언어 메타데이터 포함(아래 참조)

#### 4. 프론트메타데이터 추가

각 번역된 markdown 파일에는 언어 식별을 포함하는 YAML frontmatter가 **반드시 필요**.这是 MkDocs가 파일과 언어를 올바르게 연결하는 데 필요:

```yaml
---

title: 문서 제목
lang: ko
---
```

예: `docs/index.md` → `docs/ko/index.md`로 번역:

**번역 전 (index.md):**

```markdown
# pyrs-yaml

**High-performance Python YAML library...**
...
```

**번역 후 (docs/ko/index.md):**

```yaml
---
title: pyrs-yaml
lang: ko
---

# pyrs-yaml

**고성능 Python YAML 라이브러리...**
...
```

## 5. 탐색 제목 번역

각 번역 파일의 모든 탐색 항목 제목을 업데이트하여 대상 언어와 일치:

- `Home` → `首页` (zh)、`ホーム` (ja)、`홈` (ko)
- `Quick Start` → `快速开始` (zh)、`クイックスタート` (ja)、`빠른 시작` (ko)
- `API Reference` → `API 参考` (zh)、`API リファレンス` (ja)、`API 참조` (ko)

### 번역 프로세스

#### 수동 번역 체크리스트

각 언어에 대해 확인:

- [ ] `/lang/` 디렉토리에 모든 최상위 markdown 파일이 존재
- [ ] 모든 하위 디렉토리(`guides/`, `api/`, `contributing/`, `performance/`)에 번역된 콘텐츠가 있음
- [ ] 각 번역 파일에 올바른 `lang:` 필드가 포함된 YAML frontmatter가 있음
- [ ] 제목이 적절하게 번역됨
- [ ] 링크 참조가 올바른 상대 경로를 사용(링크에 언어 접두사 없음!)
- [ ] 번역된 파일에 번역되지 않은 영문 제목이 남아 있지 않음

### 중요 사항

#### 탐색 내 링크 참조

**내부 탐색 링크에 언어 접두사를 포함하지 마세요.** 링크는 보고 있는 언어에 관계없이 항상 동일한 상대 경로를 사용해야 합니다:

✅ **올바른 예:**

```markdown
- **[빠른 시작](quick-start.md)**
- **[API 참조](api/reference.md)**
```

❌ **잘못된 예:**

```markdown
- **[빠른 시작](ko/quick-start.md)**  # 잘못됨!
- **[API 참조](ko/api/reference.md)** # 잘못됨!
```

Material 테마는 언어 라우팅을 자동으로 처리합니다. 각 언어 버전의 모든 링크는 **동일한 언어 컨텍스트**의 다른 페이지를 가리켜야 합니다.

#### 프론트메타데이터 요구 사항

각 번역된 markdown 파일에는 YAML frontmatter가 **반드시 필요**. 최소 요구 필드:

```yaml
---
title: 페이지 제목 (번역됨)
lang: LANG_CODE
---
```

- `title`: 번역된 페이지 제목(브라우저 탭, 검색 결과에 표시)
- `lang`: i18n 설정과 일치하는 언어 코드(`languages`의 `locale` 중 하나와 일치해야 함)

#### 언어 간 일관성

모든 번역은 원본과 **구조적 일관성**을 유지해야 합니다:

- 동일한 제목 계층(#, ##, ###)
- 동일한 목록 항목과 순서
- 동일한 코드 예제(설명 텍스트는 번역)
- 동일한 테이블 구조(적절하게 헤더/콘텐츠 번역)

#### 특별한 고려 사항

##### 라이선스 파일

라이선스 파일은 가볍게 번역하면 안 되는 법적 용어를 포함하고 있으므로 특별한 주의가 필요. 실제 라이선스 텍스트는 영문으로 유지(법적 정확성)하고, 주변 설명 텍스트만 번역하는 것이 일반적:

```markdown
# 라이선스

pyrs-yaml는 다음 라이선스로 이중 라이선스:

- [MIT 라이선스](https://github.com/MuLong/pyrs-yaml/blob/main/LICENSE-MIT)
- [Apache 라이선스, Version 2.0](https://github.com/MuLong/pyrs-yaml/blob/main/LICENSE-APACHE)
```

라이선스 **텍스트 자체**는 영문으로 유지; 섹션 제목과 설명만 번역됨.

##### 코드 예제

코드 예제는 모든 언어에서 **변경해서는 안 됩니다** — 실행 가능하며 영문/Python/Rust 구문으로 유지해야 합니다:

```python
import pyrs_yaml
doc = pyrs_yaml.parse("key: value")  # 번역하지 마세요
```

코드 블록 내의 주석 문자열만 명확성을 위해 선택적으로 번역 가능.

### 검증

로컬에서 문서 사이트를 빌드하여 i18n이 올바르게 작동하는지 확인:

```bash
# 의존성 설치
uv sync

# 사이트 빌드
mkdocs build --clean-site

# 로컬에서 제공
mkdocs serve
```

`http://localhost:8000/`에 방문하여 오른쪽 상단의 언어 전환 버튼을 클릭하고 모든 언어가 올바르게 로드되는지 확인.

### 문제 해결

| 문제 | 해결책 |
|------|--------|
| 언어 전환이 표시되지 않음 | `mkdocs.yml`에서 `i18n` 블록이 올바르게 구성되고 모든 대체 언어에 일치하는 디렉토리가 있는지 확인 |
| 번역된 버전의 링크가 깨짐 | 내부 링크에 언어 접두사가 포함되지 않는지 확인(상대 경로만 사용) |
| Frontmatter가 파싱되지 않음 | 모든 번역 파일이 markdown 콘텐츠 전에 `---` YAML frontmatter로 시작하는지 확인 |
| 언어 간 검색이 작동하지 않음 | MkDocs material 플러그인은 언어별로 별도의 검색 인덱스를 생성; `--clean-site`로 재빌드 |
