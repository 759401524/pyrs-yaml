title: 站点国际化功能指南
lang: zh


## 概述

pyrs-yaml 文档现在支持 **全站国际化**，使用 MkDocs Material 主题内置的 i18n 功能。用户可以选择以下语言查看文档：**English (en)**、**中文 (zh)**、**日本語 (ja)**、**한국어 (ko)**。

#### 工作原理

Material 主题通过 `mkdocs.yml` 中的配置提供原生 i18n 支持。每种语言有独立的 URL 路径（`/zh/`、`/ja/`、`/ko/`），并使用统一的导航和语言切换功能。

```yaml
plugins:
  - i18n:
      docs_structure: folder
      languages:
        - locale: en
          default: true
          name: English
          build: true
        - locale: zh
          name: 中文
          build: true
        - locale: ja
          name: 日本語
          build: true
        - locale: ko
          name: 한국어
          build: true
```

导航会在渲染站点的右上角显示语言切换按钮。

## 添加新语言

添加新语言（例如法语）的步骤：

#### 1. 更新 mkdocs.yml

编辑 `mkdocs.yml`，添加新语言：

```yaml
plugins:
  - i18n:
      docs_structure: folder
      languages:
        - locale: en
          default: true
          name: English
          build: true
        - locale: zh
          name: 中文
          build: true
        - locale: ja
          name: 日本語
          build: true
        - locale: ko
          name: 한국어
          build: true
        - locale: fr
          name: Français
          build: true
```

如果需要，同时更新主题的默认语言：

```yaml
theme:
  name: material
  language: en   # 设置主题的默认回退语言
```

#### 2. 创建语言目录结构

```bash
mkdir docs/fr
mkdir docs/fr/guides
mkdir docs/fr/api
mkdir docs/fr/contributing
mkdir docs/fr/performance
```

#### 3. 翻译文档文件

将所有 markdown 文件从英文根目录翻译到新的语言子目录。每个翻译文件应：

- 保持相同的相对路径结构
- 在 YAML frontmatter 中包含语言元数据（见下文）

#### 4. 添加 frontmatter

每个翻译的 markdown 文件 **必须** 包含带有语言标识的 YAML frontmatter。这是 MkDocs 正确关联文件与其语言所必需的：

```yaml
---

title: 文档标题
lang: zh
---
```

例如，将 `docs/index.md` 翻译为 `docs/zh/index.md`：

## 翻译前 (index.md)：

```markdown
# pyrs-yaml

**High-performance Python YAML library...**
...
```

### 翻译后 (docs/zh/index.md)：

```yaml
---
title: pyrs-yaml
lang: zh
---

# pyrs-yaml

**高性能的 Python YAML 库...**
...
```

## 5. 翻译导航标题

更新每个翻译文件中的所有导航项标题，使其匹配目标语言：

- `Home` → `首页` (zh)、`ホーム` (ja)、`홈` (ko)
- `Quick Start` → `快速开始` (zh)、`クイックスタート` (ja)、`빠른 시작` (ko)
- `API Reference` → `API 参考` (zh)、`API リファレンス` (ja)、`API 참조` (ko)

## 翻译流程

### 手动翻译清单

对于每种语言，验证：

- [ ] `/lang/` 目录中存在所有顶层 markdown 文件
- [ ] 所有子目录（`guides/`、`api/`、`contributing/`、`performance/`）都有翻译内容
- [ ] 每个翻译文件都包含带有 `lang:` 字段的正确 YAML frontmatter
- [ ] 标题已适当翻译
- [ ] 链接引用使用正确的相对路径（链接中没有语言前缀！）
- [ ] 翻译文件中没有未翻译的英文标题

## 重要说明

### 导航中的链接引用

**不要在内部导航链接中包含语言前缀。** 链应始终使用相同的相对路径，无论您查看的是哪种语言：

✅ **正确：**

```markdown
- **[快速开始](quick-start.md)**
- **[API 参考](api/reference.md)**
```

❌ **错误：**

```markdown
- **[快速开始](zh/quick-start.md)**  # 错误！
- **[API 参考](zh/api/reference.md)** # 错误！
```

Material 主题会自动处理语言路由。每种语言版本中的所有链接都应指向 **相同语言上下文** 中的其他页面。

#### frontmatter 要求

每个翻译的 markdown 文件 **必须** 有 YAML frontmatter。最低要求字段：

```yaml
---
title: 页面标题（已翻译）
lang: LANG_CODE
---
```

- `title`：已翻译的页面标题（显示在浏览器标签页、搜索结果中）
- `lang`：与 i18n 配置匹配的语言代码（必须是 `languages` 中的 `locale` 之一）

#### 语言间的一致性

所有翻译应与原文保持 **结构一致性**：

- 相同的标题层级（#、##、###）
- 相同的列表项和顺序
- 相同的代码示例（但翻译解释性文本）
- 相同的表格结构（适当翻译标题/内容）

#### 特殊考虑

##### 许可证文件

许可证文件需要特别注意，因为它们包含不应随意翻译的法律术语。做法是保留实际许可证文本为英文（法律准确性），但翻译周围的解释性文本：

```markdown
# 许可证

pyrs-yaml 采用双重许可：

- [MIT 许可证](https://github.com/MuLong/pyrs-yaml/blob/main/LICENSE-MIT)
- [Apache 许可证, Version 2.0](https://github.com/MuLong/pyrs-yaml/blob/main/LICENSE-APACHE)
```

许可证 **文本本身** 保留英文；只有章节标题和解释被翻译。

##### 代码示例

代码示例在所有语言中应 **保持不变** —— 它们是可执行的，必须保持英文/Python/Rust 语法：

```python
import pyrs_yaml

doc = pyrs_yaml.parse("key: value")  # 不要翻译这个
```

只有代码块内的注释字符串可以为清晰起见选择性翻译。

## 验证

在本地构建文档站点以验证 i18n 是否正常工作：

```bash
# 构建站点
uv run --frozen --group docs mkdocs build

# 本地服务
uv run --frozen --group docs mkdocs serve
```

访问 `http://localhost:8000/`，点击右上角的语言切换按钮验证所有语言是否正确加载。

## 故障排除

| 问题 | 解决方案 |
|------|----------|
| 语言切换按钮不显示 | 确保 `mkdocs.yml` 中正确配置了 `plugins` 列表中的 `i18n`，且所有语言都有匹配的目录 |
| 翻译版本中链接损坏 | 验证内部链接不包含语言前缀（仅使用相对路径） |
| Frontmatter 未解析 | 确保每个翻译文件在任何 markdown 内容之前以 `---` YAML frontmatter 开头 |
| 搜索跨语言不工作 | MkDocs material 插件为每种语言生成单独的搜索索引；使用 `--clean-site` 重建 |
