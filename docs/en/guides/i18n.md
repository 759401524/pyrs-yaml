# Site-wide i18n Feature Guide

## Overview

pyyaml-rs documentation now supports **site-wide internationalization** using MkDocs Material theme's built-in i18n capabilities. This allows users to view documentation in their preferred language: **English (en)**, **Chinese (zh-CN)**, **Japanese (ja-JP)**, and **Korean (ko-KR)**.

### How It Works

The Material theme provides native i18n support through configuration in `mkdocs.yml`. Each language gets its own URL path (`/zh-CN/`, `/ja-JP/`, `/ko-KR/`) and uses consistent navigation with language switching.

```yaml
i18n:
  default_lang: en
  alternate_languages:
    - lang: zh-CN
      url: /zh-CN/
    - lang: ja-JP
      url: /ja-JP/
    - lang: ko-KR
      url: /ko-KR/
```

The navigation automatically shows language switches in the top-right corner of the rendered site.

## Adding New Languages

To add a new language (e.g., French):

### 1. Update mkdocs.yml

Edit `mkdocs.yml` to add the new language:

```yaml
i18n:
  default_lang: en
  alternate_languages:
    - lang: zh-CN
      url: /zh-CN/
    - lang: ja-JP
      url: /ja-JP/
    - lang: ko-KR
      url: /ko-KR/
    - lang: fr         # Add new language
      url: /fr/        # URL path
```

Also update the theme's default language if needed:

```yaml
theme:
  name: material
  language: en   # This sets the theme's default fallback language
```

### 2. Create Language Directory Structure

```bash
mkdir docs/fr
mkdir docs/fr/guides
mkdir docs/fr/api
mkdir docs/fr/contributing
mkdir docs/fr/performance
```

### 3. Translate Documentation Files

Translate all markdown files from the root English directory into the new language subdirectory. Each translated file should:

- Maintain the same relative path structure
- Include language metadata in YAML frontmatter (see below)

### 4. Add Frontmatter Metadata

Each translated markdown file **must** include YAML frontmatter with language identification. This is required for MkDocs to correctly associate files with their language:

```yaml
---
title: 文档标题
lang: zh-CN
---
```

For example, translate `docs/index.md` → `docs/zh-CN/index.md`:

**Before (index.md):**

```markdown
# pyyaml-rs

**High-performance Python YAML library...**
...
```

**After (docs/zh-CN/index.md):**

```yaml
---
title: pyyaml-rs
lang: zh-CN
---

# pyyaml-rs

**高性能的 Python YAML 库...**
...
```

### 5. Translate Navigation Titles

Update all navigation item titles in each translated file to match the target language:

- `Home` → `首页` (zh-CN), `ホーム` (ja-JP), `홈` (ko-KR)
- `Quick Start` → `快速开始` (zh-CN), `クイックスタート` (ja-JP), `빠른 시작` (ko-KR)
- `API Reference` → `API 参考` (zh-CN), `API リファレンス` (ja-JP), `API 참조` (ko-KR)

Use the existing translation mapping in `translate_docs.py` as reference.

## Translation Process

### Automated Script

Use the provided translation helper script:

```bash
python translate_docs.py
```

This script translates known phrases in markdown files to the target languages based on the `TRANSLATIONS` dictionary.

### Manual Translation Checklist

For each language, verify:

- [ ] All top-level markdown files exist in `/lang/` directory
- [ ] All subdirectories (`guides/`, `api/`, `contributing/`, `performance/`) have translated content
- [ ] Each translated file contains proper YAML frontmatter with `lang:` field
- [ ] Headings are translated appropriately
- [ ] Link references use correct relative paths (no language prefix in links!)
- [ ] No untranslated English headings remain in translated files

## Important Notes

### Link References in Navigation

**Do NOT include language prefixes in internal navigation links.** Links should always use the same relative paths regardless of which language you're viewing:

✅ **Correct:**

```markdown
- **[快速开始](quick-start.md)**
- **[API 参考](api/reference.md)**
```

❌ **Incorrect:**

```markdown
- **[快速开始](zh-CN/quick-start.md)**  # Wrong!
- **[API 参考](zh-CN/api/reference.md)** # Wrong!
```

The Material theme handles language routing automatically. All links within each language version should point to other pages in the **same language context**.

### Frontmatter Requirements

Every translated markdown file **must** have YAML frontmatter. The minimum required fields are:

```yaml
---
title: Page Title (translated)
lang: LANG_CODE
---
```

- `title`: Translated page title (displayed in browser tab, search results)
- `lang`: Language code matching the i18n config (must match one of `alternate_languages.lang`)

### Consistency Across Languages

All translations should maintain **structural consistency** with the original:

- Same heading hierarchy (#, ##, ###)
- Same list items and order
- Same code examples (but translated explanatory text)
- Same table structures (with translated headers/content where appropriate)

### Special Considerations

#### License File

License files require special attention because they contain legal terms that should not be lightly translated. The practice is to keep the actual license text in English (legal accuracy) but translate surrounding explanatory text:

```markdown
# 许可证

pyyaml-rs is dual-licensed under either:

- [MIT 许可证](https://github.com/MuLong/pyyaml-rs/blob/main/LICENSE-MIT)
- [Apache 许可证, Version 2.0](https://github.com/MuLong/pyyaml-rs/blob/main/LICENSE-APACHE)
```

The license **text itself** remains in English; only section headings and explanations are translated.

#### Code Examples

Code examples should **remain unchanged** across languages — they are executable and must stay in English/Python/Rust syntax:

```python
import pyyaml_rs
doc = pyyaml_rs.parse("key: value")  # DO NOT TRANSLATE THIS
```

Only comment strings inside code blocks may optionally be translated for clarity.

## Verification

Build the documentation site locally to verify i18n works correctly:

```bash
# Install dependencies
uv sync

# Build the site
mkdocs build --clean-site

# Serve locally
mkdocs serve
```

Visit the site at `http://localhost:8000/` and click the language switcher in the top-right corner to verify all languages load correctly.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Language switcher not showing | Ensure `i18n` block is properly configured in `mkdocs.yml` and all alternate languages have matching directories |
| Broken links in translated version | Verify internal links don't include language prefixes (use relative paths only) |
| Frontmatter not parsed | Ensure every translated file starts with `---` YAML frontmatter before any markdown content |
| Search doesn't work across languages | MkDocs material plugin generates separate search indexes per language; rebuild with `--clean-site` |
